# Security review — 14 November 2026

## الحدود الحالية

- **JPL Horizons**: مدخلات محدودة ومتحقق منها عبر Zod، مصدر HTTPS ثابت، لا URL يتحكم به المستخدم، ولا أرقام بديلة عند الفشل.
- **دوال الخادم**: CSRF middleware على كل `serverFn`، وترويسات أمان على كل استجابة SSR.
- **الحدود**: 30 طلب JPL/دقيقة لكل IP و12 طلب فحص SEO/دقيقة لكل IP، مع كاش وتجميع طلبات.
- **الخصوصية**: لا حسابات ولا قاعدة بيانات. تُرسل الإحداثيات إلى خادم الموقع ثم JPL فقط عند التقييم. لا تُسجل الإحداثيات في سجلات الأخطاء.
- **الأصول**: الصور والتضاريس والخطوط من نفس النطاق (`public/assets`, `public/fonts`)؛ لا اتصال بـ Lovable أو Google Fonts.
- **«سيلين الذكية» (اختياري)**: تُرسل إلى NVIDIA فقط عند سؤال صريح — نص السؤال + الاسم + التاريخ + الساعات المحسوبة (بلا إحداثيات ولا مفاتيح من المتصفح). المفتاح في `.env`/`.dev.vars` المحليتين أو `wrangler secret` للإنتاج؛ لا يُرفع أبدًا.
- **التصدير**: لا قيم بيئة أو ملفات اعتماد أو Git metadata أو تبعيات مثبتة داخل مخرجات المصدر.

## التغييرات في هذه المراجعة

- إزالة Lovable بالكامل: `.lovable/`, `src/integrations/`, `@lovable.dev/*`, وكل مسارات `__l5e`.
- إزالة Supabase وDrizzle وبوابة AI وإدارة SEO المحمية؛ صفحة `/seo` أصبحت فحصًا عامًا للقراءة فقط.
- نقل بلاطات LOLA وصورة LROC والخطوط إلى `public/` مع التحقق من SHA-256.
- استبدال `redirect: "error"` بـ`"manual"` في طلبات JPL وsitemap لأن Cloudflare Workers يرفض الأولى.
- تحميل التضاريس حسب التغطية الفعلية وعند الطلب فقط، مع رفض البلاطة غير المغطية بدل تمريرها خطأً.
- إصلاح حساب الحد الأدنى للبطارية قبل تطبيق حد الاحتياطي.
- إضافة CSP و`_headers` و`/privacy`.
- إضافة اختبارات لتغطية التضاريس، حد البطارية، حد المعدل، وسياسة إعادة التوجيه.
- إضافة تكامل NVIDIA اختياري (`selene-ai.functions.ts`): حد 4/دقيقة + 10/يوم لكل IP و200/يوم النظام، كاش 24h، أدوات قراءة فقط، ورد ≤350 رمزًا بالعربية.
- إضافة صفحة `/team` وبيانات الفريق في `src/lib/team.ts` (قابلة للتعديل) وصور مميزة مؤقتة في `public/team/`.
- تحويل الواجهة إلى العربية بالكامل مع RTL وخط IBM Plex Sans Arabic المستضاف محليًا.

## التحقق

- `bun run test`: 18 ملفًا / 58 اختبارًا ناجحًا.
- `bunx tsc --noEmit`: بلا أخطاء.
- `bun run build`: ينجح وينتج `.output` مع `privacy` و`_headers` والأصول المحلية.
- فحص يدوي محلي: كل المسارات العامة تُرجع 200، و`sitemap.xml` يحتوي الصفحات المتوقعة، و`getLunarScenario` يعيد بيانات JPL حقيقية، و`getSeoAudit` يقرأ sitemap المنشور.
- `bun run lint`: يُشغَّل قبل التسليم النهائي.

## حدود متبقية

- حد المعدل داخل isolate وليس حصة عالمية؛ يلزم WAF أو حد على مستوى المنصة للحماية الصلبة.
- فحص SEO يقرأ النطاق المنشور `https://synexiss.site`، لذا يعكس آخر نشر وليس نسخة التطوير المحلية.
- لا يمكن ضمان خلو أي تطبيق من الأخطاء. راجع الاعتماديات والافتراضات العلمية عند تغيير البيانات أو الإعدادات.
